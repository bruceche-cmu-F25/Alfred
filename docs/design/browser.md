# 浏览器：Alfred 用你登录过的 Chrome（草案）

> 状态：v0.2（2026-11-19），**先存着**。Bruce 2026-11-19："这种 feature 也先存着，到时候再考虑怎么做"。没有批准，什么都还没做；第 7 节六个问题到时候再定。v0.2 加了打包（3.6 节、第 7 节第 6 条）。
> 起因：Bruce 2026-11-19 说，B 站和小红书的登录墙要靠"Alfred 去操控我的浏览器，直接在我登录过的 Chrome 里"来解决。这会改掉 `links.md` 第 5 节的"不碰你的 Chrome"。
> 依据：`docs/design/links.md`（4.2、4.3、4.9、第 5 节）；`modules/links/src/fetch.ts`、`url.ts`；`packages/engine-pi/src/connectors.ts`、`worker.ts`（工具的闸门）；BrowserSkill 的 README、`docs/mcp.md` 和本机 `bsk --help`；Chrome 开发者文档（远程调试开关的变化、auto-connect）；Playwright MCP 的扩展文档。
> 标记：**【事实】** 读文档、读代码或在本机跑命令核实过；**【未实测】** 我知道的或文档说的，没在你的浏览器里跑过；**【建议】** 本方案的提案；**【待定】** 第 7 节。

## 0. 结论

1. **Playwright 直连走不通，要走扩展。** Chrome 136 起不让调试端口连日常的用户资料。能进到"你登录过的那个 Chrome"的路只有装扩展，或 Chrome 自己的开关。
2. **用 bsk（腾讯 BrowserSkill）。** 它在后台开一个单独的"Agent 窗口"，不抢你的标签页，配对一次就记住。你机器上已经装了。
3. **Links 里是固定的一步，不是让模型开浏览器。** 打开那条链接、取文字、关掉，三件事由代码做。取回的文字再交给没有工具的 `reader`。
4. **只去你点过头的站点**，先是 `bilibili.com` 和 `xiaohongshu.com`。
5. **不等 L2 也有用。** 这一步先把 B 站和小红书卡片上的标题、作者、封面、简介补上；正文和字幕的总结等 L2。
6. **"Alfred 在对话里自己开着浏览器做事"是另一件事**，风险大得多，这份文档只留位置，不建议现在做。

## 1. 要解决什么

【事实】`links.md` 4.3 的实测：

| 站 | 现在 | 原因 |
|---|---|---|
| Bilibili | 卡片只有 `bilibili.com · BV…`，标"没取到标题" | 页面和公开接口只回答浏览器；Alfred 照实报身份，拿到空壳和 412 |
| 小红书 | 卡片标"要登录才看得到" | 笔记页直接跳登录页 |
| X、微博等 | 只到标题 | 多数要登录 |

Alfred 不冒充浏览器，也不带 cookie（`fetch.ts`）。所以这几类站，Alfred 自己去取永远拿不到。你的 Chrome 拿得到：它本来就是浏览器，本来就登录着。

## 2. 查到的事实

### 2.1 为什么不是 Playwright

【事实】Chrome 136 起，`--remote-debugging-port` 和 `--remote-debugging-pipe` 对默认的用户资料目录不生效，必须另给一个 `--user-data-dir`。你的 Chrome 是 158。另起的资料目录里没有你的登录，等于再登一次。

### 2.2 三条能走的路

| | bsk（BrowserSkill） | Chrome 自带 | Playwright MCP Bridge |
|---|---|---|---|
| 是什么 | 扩展 + 本机后台服务 + 命令行；MIT | `chrome://inspect/#remote-debugging` 的开关（144+），配 `chrome-devtools-mcp --autoConnect` | 微软的扩展，配 `@playwright/mcp --extension` |
| 同意 | 配对一次，记得住 | **每次连接弹"允许"** | Chrome 每次重启点一次 |
| 在哪干活 | 单独的 Agent 窗口，默认在后台；你的标签要"借"才能动 | 你当前的窗口和标签 | 你选的标签 |
| 给代码用 | 命令行，每条命令出 JSON | 只有 MCP | 只有 MCP |
| 往外发数据 | README 说没有遥测、不经云【未实测】 | 默认向 Google 发用量统计，有开关可关 | |

【事实】本机：`~/.local/bin/bsk`，0.4.1，skill 已同步到 pi。`bsk doctor` 说后台服务没在跑，所以扩展连没连上现在看不出来。它还报告"自动更新 0.4.2 → 0.5.0 成功"，和 0.4.1 对不上，B1 里要查清是不是装了两份。

【事实】bsk 的 Agent 窗口**和你共用登录状态，不是沙箱**（它 README 的原话）。能进这个窗口，就能以你的身份去任何登录过的站。

### 2.3 为什么选 bsk【建议】

- Links 要的是无人看着也能跑的一步。Chrome 自带那条每次弹框，你不在电脑前就卡住。
- 固定的一步由代码发命令，要的是命令行，不是 MCP。三条里只有 bsk 有。
- 后台窗口，不打断你正在看的东西。

代价：信任一个第三方扩展（能读所有站点）和一个会自己更新的二进制。见第 4 节。

## 3. 方案

### 3.1 两种用法，分开对待

| | 固定的一步 | Alfred 自己开浏览器 |
|---|---|---|
| 谁决定去哪 | 代码：只去你收下的那条网址 | 模型 |
| 能做什么 | 打开、读、关掉 | 点、填、提交 |
| 网页里的话谁看到 | 没有工具的 `reader` | 手里有浏览器的模型 |
| 这份文档 | **B1–B3，建议做** | B4，只留位置 |

### 3.2 接法【建议】

```text
主节点（Mac 上）
  └─ packages/server/src/browser.ts      唯一能启动 bsk 的地方
        ├─ 状态：装了没、后台服务在不在、扩展连上没、是哪个浏览器
        ├─ read(url) → { 标题、作者、封面、简介、正文、字幕 } 或一个失败原因
        └─ 许可的站点清单
  └─ module-kit 多一个 `browser` 能力     模块只能调 read，不能自己起进程
        └─ modules/links 在取标题失败（原因 login）时用它
```

- **后台服务由主节点管**：主节点启动时把 `bsk daemon start --foreground` 当子进程带起来，退出时带走。
- **设置里多一块「浏览器」**：连没连上、连的是哪个浏览器、许可的站点。扩展没装时给一个直达商店页的按钮（3.6）。
- **bsk 藏在 `browser.ts` 后面**：以后换成 Chrome 自带那条，或者 Alfred 自己的扩展，模块不用改。
- 手机上收一条小红书也走这条路：干活的是 Mac 上的主节点。

### 3.3 读一页的过程

```text
bsk session start --no-focus          后台开 Agent 窗口
  → navigate <url>                    只这一条网址
  → wait-for-navigation               有时限
  → 检查落在哪：还是那个站吗？是登录页或验证页吗？
  → evaluate <写死在代码里的表达式>    取页面自己已经有的数据
  → session stop                      无论成败都关
```

规矩，写死在 `browser.ts`：

- **只读。** 不点、不填、不提交、不滚动加载。`evaluate` 的表达式是仓库里的代码，不是模型写的；它只读页面上已有的东西，不向别的地址发请求。
- **网址的主机必须在许可清单里**，跳转后再查一次；跳出了清单就停。
- **一次一页。** 两页之间隔开几秒，每天有上限（和 Links 的每日上限共用）。
- 限时 20 秒，取回的文字有长度上限。
- 落在登录页或验证页：原因记 `login`，卡片说"在 Chrome 里登录一下这个站"。Alfred 不碰登录和验证码。

### 3.4 每个站的读法

【未实测】下面是我知道的页面结构，B2 开工第一件事是在你的 Chrome 里核实。

| 站 | 取什么 | 依据写什么 |
|---|---|---|
| Bilibili | 页面状态里的标题、UP 主、封面、简介、时长；字幕轨（AI 字幕要登录才列得出） | "根据字幕" / 没字幕时"根据简介" |
| 小红书 | 页面状态里的标题、作者、正文、封面 | "根据正文" |
| 其他许可的站 | 页面的 HTML，走 L1 已有的那套提取 | "根据正文" |

两件已知的坑：

- **小红书的图文笔记，内容常在图里。** 文字只有一两句。要读图得截图给视觉模型，依赖多文件输入那条线，这版不做，卡片照实说"只读到配文"。
- **小红书的链接要带 `xsec_token` 才打得开。**【事实】`url.ts` 清跟踪参数的表里没有它，所以现在是留着的；以后改那张表要记得。

### 3.5 没连上怎么办【建议】

Chrome 没开、扩展没连上、bsk 没装：卡片说"等浏览器"，排着。连上以后主节点自己补读。Alfred 不替你打开 Chrome。

### 3.6 打包【建议，Bruce 2026-11-19 要的】

装完 Alfred 尽量就齐，但扩展那一半打不进去。

| 部件 | 能随 app 带吗 | 说明 |
|---|---|---|
| `bsk` 命令行和后台服务 | 能 | 【事实】一个单独的二进制，MIT；0.5.0 的 Apple 芯片版约 7 MB，Intel 版约 8 MB |
| Chrome 扩展 | 不能 | Chrome 不让别的 app 静默装扩展，只能从应用商店装，用户自己点同意 |
| 网站的登录 | 不能 | 用户自己在 Chrome 里登 |

所以用户装好 Alfred 后还有两步：在商店点一次"添加扩展"，在扩展里打开连接。设置里给按钮和连接状态。

- **版本会错开。** 扩展由 Chrome 自动更新，随 app 带的命令行是固定的一版，两边的协议版本要对上（`bsk doctor` 有这项检查）。两个办法：Alfred 跟着发新版；或者不随包带，第一次用时下载、以后按需更新。开工时定。
- **随包带的那份由 Alfred 决定版本**，这能减轻"它会自己更新"的担心（第 4 节），前提是它的自更新关得掉。【未实测】还没找到这个开关。
- **签名。** 包里的二进制要跟 app 一起签名和公证。
- Chrome 有个"外部扩展"的办法（app 往 Chrome 的目录放一个文件，Chrome 提示用户启用）。【未实测】用户仍要点同意，也没查到现在的 Chrome 还认不认，不指望它。
- 打包本身排在最后（Alfred.app 的打包整体还没做）。

## 4. 安全和隐私

- **这是 Alfred 第一次用你的身份去网上。** 固定的一步把范围压到最小：只读、只去清单里的站、只开你收下的网址。
- **扩展本身能读所有站点。** 清单限制的是 Alfred 发什么命令，限制不了 bsk 这个扩展。信任 bsk，是信任腾讯这个开源项目。我只读了它的 README，没审代码。
- **bsk 会自己更新**（`doctor` 里看到）。所以信任的是它今后的每一版，不只是今天这一版。B1 里查它能不能关掉自动更新、改成你点了才更。
- **网页里的话。** 小红书正文是别人写的，可能有冲着模型说的话。它只进 `reader`，那次调用没有工具（`links.md` 第 5 节）。
- **账号风险。**【未实测】小红书对自动化查得严。一次一页、有间隔、有上限，和你自己点开差不多；但不能保证不触发验证。触发了 Alfred 就停，等你自己处理。
- **对网站来说**，这就是你本人打开了那一页：算进你的浏览记录和推荐。
- **许可清单只能在 Mac 上改。** 手机能收链接、能看状态，不能加站点。
- **和原方案比**：原来是 Alfred 自带浏览器，你扫码登一次，里面只有这两个站的登录，碰不到别的。这个方案换来的是不用再登一次、以后别的站也能用；付出的是上面第二、三条。

## 5. 搭建顺序

1. **B1 连接**：`browser.ts`（状态、带起后台服务）、设置里的「浏览器」、许可清单、bsk 版本和自动更新查清。做完能看到"已连上你的 Chrome"。
2. **B2 补上标题**：`read(url)`、B 站和小红书两个读法、Links 在 `login` 失败时改走浏览器、"等浏览器"的排队、卡片上的新说法。**做完 B 站和小红书的卡片就有标题、作者、封面、简介了**，不依赖 L2。
3. **B3 正文和字幕**：把取回的正文和字幕交给 `reader`。跟着 Links L2 一起做。
4. **B4 Alfred 自己开浏览器**【不建议现在做】：把 `bsk mcp` 接成连接器，零代码就能试。但要先想清楚两件事：现在的闸门是每次调用问一次（`worker.ts`），浏览一个任务要问二十次；模型点一个链接就能离开许可的站，Alfred 拦不住。要做时单写一份文档。

开发页里的浏览器（看预览用的那个）是另一件事，另有文档，和这份没有交点。

## 6. 不做

- 不让 Alfred 登录、过验证码、改账号设置。
- 不读你的浏览历史、书签、别的标签页；不"借"你开着的标签。
- 不读 Chrome 的 cookie 文件拿去自己发请求。
- 不批量抓：不翻页、不抓评论区、不顺着推荐往下读。
- 不替用户装 Chrome 扩展（也装不了）；扩展没连上就照旧只到标题。

## 7. 需要你决定

| # | 问题 | 建议 | 影响 |
|---|---|---|---|
| 1 | 走哪条路 | bsk | 要信任一个第三方扩展和它的自动更新；换来不弹框、后台窗口、命令行 |
| 2 | 用哪个 Chrome 资料 | 你日常的那个（你说的）。另一个选法：给 Alfred 单开一个 Chrome 资料，只登这两个站 | 日常资料不用再登录，但 bsk 碰得到你所有的登录；单开资料要登一次，隔得干净 |
| 3 | 许可过的站，收下就自动用浏览器读，还是每次点 | 自动；一次一页，有间隔，有每日上限 | 收下就有标题；自动的次数越多，触发验证的可能越大。这会改掉 `links.md` 4.3 的"不自动" |
